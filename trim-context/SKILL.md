# trim-context

รับ path มาทาง argument. **ไม่มี path มา → ถามก่อน อย่าเดา** (มี `CLAUDE.md` ใน cwd ก็เสนอไป
แต่ยังต้องให้ยืนยัน — trim ผิดไฟล์คือลบงานคนอื่นทิ้ง)

เอกสารพวกนี้บวมด้วยกลไกเดียวเสมอ: **ทุกกฎลากประวัติที่ทำให้ได้กฎนั้นมาด้วย**
งานของสกิลนี้คือแยกสองอย่างนี้ออกจากกัน แล้วเก็บไว้อย่างเดียว

## ⛔ เช็กชนิดเอกสารก่อน — ไม่ใช่ทุก doc ใช้สกิลนี้ได้

สกิลนี้ตัดโดยถามว่า "ไม่รู้แล้วทำผิดไหม" ซึ่งใช้ได้เฉพาะเอกสารที่คนอ่าน**เพื่อไปลงมือทำ**

**ใช้ได้:** เอกสารบริบท/สั่งงาน — CLAUDE.md, AGENTS.md, SKILL.md, runbook, playbook,
onboarding, README ส่วนที่เป็นวิธีใช้

**⛔ ห้ามใช้ — หยุดแล้วบอกเจ้าของว่าทำไม อย่าตัดให้:**

| เอกสาร | ตัดแล้วพังตรงไหน |
|---|---|
| postmortem / ADR / บันทึกการตัดสินใจ | "เรื่องเล่าว่าได้ข้อสรุปมายังไง" คือทั้งไฟล์ — สกิลนี้สั่งตัดตรงนั้นก่อนเลย |
| สเปก / requirement / design doc | ความครบคือคุณค่า ตัดแล้วกลายเป็นข้อตกลงที่หายไป |
| บทความ / tutorial / เอกสารสอน | คำอธิบายคือของที่ขาย ไม่ใช่ไขมัน |
| changelog / API reference / เอกสารอ้างอิง | ตัด = ข้อมูลหาย ไม่ใช่กระชับ |
| เอกสารกฎหมาย/สัญญา/นโยบาย | ไม่ใช่งานของสกิลนี้ |

ก้ำกึ่ง (เช่นไฟล์ที่มีทั้ง runbook และ postmortem ปนกัน) → **ถามก่อน** หรือเสนอตัดเฉพาะส่วน
ที่เป็นวิธีทำ แล้วปล่อยส่วนบันทึกไว้ทั้งก้อน

## เกณฑ์เดียวที่ใช้ตัดสิน

> **ถ้า session อื่น (หรือคนอื่น) ไม่รู้บรรทัดนี้ เขาจะทำผิดหรือหลงทางแน่ไหม**
> ไม่แน่ = ตัด

### เก็บ

- **ข้อห้ามที่พลาดแล้วแก้คืนไม่ได้** — ของถาวร ลบไม่ได้ เสียเงิน ส่งออกไปข้างนอกแล้ว
- **คำสั่ง/พาธ/ชื่อไฟล์/ID** ที่ต้องรู้ถึงจะเริ่มงานได้
- **กับดักที่มองจากโค้ดไม่เห็น** — พฤติกรรมเงียบ, ของที่ดู idempotent แต่ไม่ใช่,
  dependency ที่ต้องมีก่อนถึงจะรันได้, ค่าที่ต้องตรงกันสองที่
- **"อย่ารื้อซ้ำ"** — ทางตันที่พิสูจน์แล้ว เหลือบรรทัดเดียวว่าอย่าไปลองใหม่ (อันนี้มีค่าสูง
  เพราะไม่มีใน git history และเป็นของที่คนถัดไปจะไปเสียเวลาซ้ำ)
- **กฎภายนอกที่เราไม่ได้ตั้งเอง** — กติกาแพลตฟอร์ม ลิมิต สเปกบังคับ
- **ของที่ขัดสัญชาตญาณ** — ที่คนอ่านโค้ดแล้วจะสรุปตรงข้าม

### ตัด

- **เรื่องเล่าว่าข้อสรุปได้มายังไง** — เก็บข้อสรุป ทิ้งการสืบสวน (ตัวตัดที่แรงสุด)
- วันที่ / commit hash / ตัวเลขการทดลอง ที่ไม่เปลี่ยนว่าต้องทำอะไรต่อ
- ฟีเจอร์ที่ปิดไปแล้ว/เลิกใช้ — เหลือแค่ "อย่าเปิดใหม่" ถ้ามีเหตุผลจริง
- รายละเอียดที่โค้ดกันไว้ให้แล้ว (คนแก้โค้ดจะเห็นเอง)
- ประวัติเคสรายชิ้น **เว้นแต่เคสนั้นคือตัวกฎเอง** — ถ้ากฎเข้าใจยากโดยไม่มีเคส เก็บเคสไว้
  ประโยคเดียวติดกับกฎ
- deadline/วันตัดสินใจที่ผ่านไปแล้ว, ตาราง trial ที่จบไปแล้ว

## ขั้นตอน

**1. สำรองก่อน** ลงโฟลเดอร์ scratchpad ของ session (ไม่ใช่ในโปรเจกต์) แล้วบอก path สำรองไว้

**2. อ่านทั้งไฟล์** ไม่ใช่ grep หัวข้อ — ของที่ต้องเก็บมักซ่อนอยู่กลางย่อหน้าที่ตัดทิ้งทั้งก้อน

**3. เขียนใหม่ทั้งไฟล์ ห้ามลบทีละบรรทัด** ลบทีละจุดจะได้ไฟล์สั้นลงแต่รกเหมือนเดิม
เพราะโครงเดิมยังอยู่ · **ยกข้อจริงที่สำคัญที่สุดของโปรเจกต์ขึ้นหัวไฟล์** ให้กฎอื่นอ้างมันได้
แล้วกฎที่กระจัดกระจายจะยุบรวมกันเอง

**4. diff เชิงกลไก — ขั้นนี้ห้ามข้าม** ดึงตัวระบุออกจากไฟล์เก่า เทียบกับไฟล์ใหม่:

```bash
python3 - <<'PY'
import re, pathlib
old = pathlib.Path("<ไฟล์สำรอง>").read_text()
new = pathlib.Path("<ไฟล์ใหม่>").read_text()
pat = re.compile(
    r"[\w./-]+\.(?:py|js|ts|sh|md|json|jsonl|yaml|yml|toml|ttf)\b"  # ไฟล์
    r"|--[a-z][\w-]*"                                              # แฟล็ก CLI
    r"|\b[A-Z][A-Z0-9]*_[A-Z0-9_]+\b"                              # CONST_NAME
    r"|\b[a-z]+_[0-9A-Za-z]{8,}\b"                                 # id ของระบบ (trig_x, env_x)
    r"|https?://[^\s)>`]+"                                         # URL
    r"|\b\d+×\d+\b|\b\d{1,3}(?:,\d{3})+\b"                     # สเปก 1600×800 / 1,500
    r"|\b(?:node|issue|PR)/\d+\b")                                # เลขอ้างอิงของแพลตฟอร์ม
missing = sorted(set(pat.findall(old)) - set(pat.findall(new)))
print("หายไปจากไฟล์ใหม่:", *("  - " + m for m in missing), sep="\n")
PY
```

ไล่ทีละอันว่า **ตัดเพราะอะไร** ถ้าตอบไม่ได้ = ตัดผิด เติมกลับ (regex จับได้ไม่ครบทุกแบบ
ถ้าเอกสารมีตัวระบุทรงอื่น เติม pattern เอง)

**5. รายงานก่อน commit** — ตัวเลขก่อน/หลัง (bytes + บรรทัด), **หมวดที่ตัดออก** เป็นบุลเล็ต,
**สิ่งที่ยังอยู่ครบ** เป็นลิสต์กฎสั้นๆ, และจุดที่ตัดผิดแล้วเติมกลับตอนข้อ 4

**ห้าม commit เอง** เอกสารนี้คือของที่ทุก session อ่าน เจ้าของต้องได้ดูก่อน

## กับดัก

- **ตัดจนเหลือแต่โครง** — เป้าไม่ใช่ "สั้นที่สุด" แต่คือ "ไม่มีอะไรที่ตัดแล้วมีคนพัง"
  ปกติจะลงเอยราว 40–60% ของเดิม ถ้าเหลือ <25% ให้สงสัยว่าตัดกฎไปด้วย
- **เจอของที่ดูไม่มีใครใช้แล้ว = รายงาน ไม่ใช่ลบเงียบ** อาจมีคนอื่น/routine อื่นอ้างอยู่
- **อย่าเปลี่ยนกฎตอน trim** งานนี้คือย้ายกับตัด ไม่ใช่แก้เนื้อกฎ — จะแก้ให้แยกรอบ
- **ตัวเลขสเปกกับพาธห้ามย่อ** "ประมาณ 1500 ตัวอักษร" ไม่เท่ากับ "≥ 1,500" ตัวเลขคือกฎ
