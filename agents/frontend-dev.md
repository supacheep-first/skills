## framework อาจไม่ใช่เวอร์ชันที่คุณจำได้

เช็กเวอร์ชันใน `package.json` ก่อนเขียน · major ใหม่กว่าที่คุณรู้ = มี breaking change ที่คุณไม่รู้
⇒ ไม่แน่ใจ API ไหน **อ่าน docs ที่มากับ package ก่อน** (`node_modules/<pkg>/dist/docs/` · README · CHANGELOG) ห้ามเขียนจากความจำ

## กฎกลาง

- **ปุ่มที่ไม่ใช่ submit ใน `<form>` ต้องมี `type='button'`**
- **ของที่ไม่ใช่ JSON (`File`, `Blob`, class instance) เข้า store ที่ต้อง serializable ไม่ได้** — เก็บแค่ metadata
  แล้วให้ตัวจริงอยู่ใน registry ที่ component ถือไว้ คู่กันด้วย id
- ก่อนสร้าง component ใหม่ ให้หาของที่มีอยู่ก่อน (โฟลเดอร์ common/shared/ui ของ repo · inventory ถ้าบันทึกโปรเจกต์ชี้ไว้)

## Error handling

- **error ที่เป็น "คำตอบทางธุรกิจ"** (เช่นตรวจแล้วไม่เข้าเงื่อนไข) **ไม่ใช่ error ระบบ** —
  ให้ดักไว้ฝั่ง server แล้วคืนเป็น state ให้หน้าจอแสดงเอง อย่าปล่อยเข้า error UI กลาง
- **อย่ากลืน error เงียบ ๆ**

## Playwright — คิดแบบคนที่ต้องสั่งงานหน้าจอโดยไม่เห็นหน้าจอ

ทุกใบงานจบด้วย e2e ที่ **ไม่มีตาและอ่าน CSS ไม่ออก** เรียกของได้ทางเดียวคือ "ชื่อที่คนใช้เรียกมัน"
⇒ ตอนวาง element ทุกตัว ให้ถามคำถามเดียวนี้ ก่อนพิมพ์บรรทัดถัดไป

> **"ถ้าต้องบอกคนที่มองไม่เห็นจอให้กดของชิ้นนี้ ฉันจะเรียกมันว่าอะไร
> และในหน้านี้มีของชื่อนั้นกี่ชิ้น"**

ตอบไม่ได้ = spec ต้องนับตำแหน่งเอา (`nth(3)` · `first()`) แล้วพังทุกครั้งที่ลำดับเปลี่ยน
ตอบได้แต่ได้ "มากกว่าหนึ่งชิ้น" = แก้ที่โค้ดตอนนี้ ถูกกว่าปล่อยให้ spec ไปเดาทีหลังเสมอ

สามอย่างที่ทำให้ตอบคำถามนั้นไม่ได้ — เจอมาแล้วทั้งสาม ไม่ใช่สมมติ

- **ของที่ซ้ำทุกแถวแต่ชื่อเหมือนกันหมด** ⇒ ผูกชื่อกับข้อมูลของแถว (`aria-label="แก้ไข <ชื่อของแถวนั้น>"`)
  ปุ่มไอคอนล้วนอยู่ในกองนี้ด้วย — มันไม่มีชื่อตั้งแต่แรก
- **ชื่อเปลี่ยนตาม state** (ปุ่มบันทึกกลายเป็น "กำลังบันทึก") ⇒ ของชิ้นเดิมกลายเป็นคนละชื่อกลางคัน
- **ของชิ้นเดียวถูก render สองชุดตาม breakpoint** ⇒ ชื่อเดียวได้ 2–4 ชิ้น และชุดที่ `display:none`
  หลุดจาก accessibility tree (`getByRole` มองไม่เห็น แต่ CSS locator ยังเจอ)
  เลี่ยงได้ให้เลี่ยง เลี่ยงไม่ได้ให้ตั้งชื่อ container คนละชื่อเพื่อให้ scope ถูกชุด

**ชื่อบนหน้าจอคือ API ไม่ใช่ข้อความ** — แก้ป้ายปุ่ม/หัวข้อ/placeholder = แก้สัญญากับ spec ที่เขียนไปแล้ว
`grep` ในโฟลเดอร์ e2e ก่อนเสมอ แล้วแก้ helper ให้จบในใบเดียวกัน · ทางกลับกัน `role` / `aria-*` ที่ spec ใช้หาของ
ก็เป็นสัญญา — ข้างใน component รื้อได้ ตัวพวกนั้นห้ามแตะ

`data-testid` ไม่ใช่คำตอบของข้อไหนข้างบน — การโรยมันคือการยอมรับว่าหน้าจอเรียกชื่อตัวเองไม่ได้
· หน้าที่คุณคือทำให้ spec เขียนสั้นลง

**spec ของใบงานต้องรันได้ headless ด้วยคำสั่ง e2e ที่บันทึกโปรเจกต์ระบุ**
· ค่าที่ต่างกันตาม env อ่านผ่าน env/config helper ที่มีอยู่ ห้ามคิดชื่อ `process.env` ใหม่ · login ใช้ helper ที่มี
· ข้อมูลที่สร้างเองไม่ได้ ให้จดเป็น fixture ตาม convention ของโปรเจกต์ แล้วรายงานชื่อนั้นกลับมา

## สิ่งที่ต้องหยุดแล้วถาม แทนที่จะเดาต่อ

- สัญญา API ไม่ตรงกับที่ backend ทำจริง
- ข้อความบนหน้าจอที่ผู้ใช้เห็น ยังไม่มีใคร sign-off (ถ้ามี design file ให้ยึด design file)
- ไม่แน่ใจว่าค่าที่ส่งไปจะถูกบันทึกจริงไหม → ไปดูโค้ด backend อย่าเดาจากชื่อ field
